---
name: sayintel-new-conference
description: Start a sayintel campaign from a conference speaker or agenda URL and follow the run until drafts are ready.
argument-hint: <conference-url> [client name]
---

Start a new sayintel campaign for this conference: $ARGUMENTS

The text after the command is a conference URL, optionally followed by the client it is for. Use only the read and write tools of the `sayintel` MCP server. Nothing sends from this connection.

1. Call `whoami`. Note the account's clients.
2. If the account has clients and the user did not name one, ask which client this conference is for, or whether it is for their own company. Never pick a client yourself. Map the name to its `client_id` from `whoami`. An account with no clients gets neither `client_id` nor `own_company`.
3. Check for a campaign that already covers this conference, inside the chosen client only. `list_campaigns` shows names, not URLs or clients, so use it only to find likely candidates by name. Open each candidate with `get_campaign` and count it as a match only when its `client_id` is the client the user chose (or is empty, for their own company) and its conference URLs include this URL. If one matches, offer to follow it instead. Never offer a campaign that belongs to another client, even for the same URL.
4. Call `create_campaign` with `dry_run: true`, the `conference_url`, `conference_date` if you know it, and the ownership fields from step 2. This preview does not create a campaign. `cost_preview.credits_estimated` is 0 because the roster has not been scraped. Say that in one line: creating the campaign costs nothing, and this zero is not the enrichment cost. Do not ask the user to approve a paid run from this number.
5. Ask to create the campaign and scrape the speaker list without starting the paid run. On a yes, call `create_campaign` again with `auto_start: false`. The default is `auto_start: true`, and that starts the pipeline immediately, so you must pass false. If `warning` says there is no pitch, tell the user the run will park before research until they add one, and ask for it.
6. Poll `get_run_status(campaign_id)` every 15 to 30 seconds. Read `urls[].scrape_status`, `urls[].scrape_error`, and `counts.speakers`. Keep waiting while a URL is `pending`, `scraping`, or `paginating`. Stop and show `scrape_error` when `scrape_status` is `error`. A finished scrape is `done`. Do not start a paid run while `counts.speakers` is still 0. `get_run_status` does not return `staleness_warning`, so the roster gate is visible only in `scrape_error`. A completion note that contains none of the phrases below can continue. If `scrape_error` contains `roster_unchecked`, `roster_thin`, "not confirmed complete", or "no roster size advertised", the paid start will be refused. A "roster incomplete:" or "captured N of ~M" note is also refused when it captured fewer than 25 names or less than 40 percent of the advertised size. Tell the user, and ask whether to scrape again or research the names already captured. A captured list of at least 25 names and at least 40 percent of the advertised size can continue. Do not ask them to approve a run the server will skip.
7. When the roster is in and step 6 did not block it, call `start_campaign_run(campaign_id, dry_run: true)`. Show `credits_estimated`, how many speakers are already enriched, the credit balance, and the note that a later scrape can add speakers and raise the cost. Ask before spending. This dry run does not apply the roster gate, so the preview is the price, not proof the start will be accepted.
8. On a yes, call `start_campaign_run` without `dry_run`. If `ok` is false and `skipped` is `roster_unchecked`, no run started. Show `error` and stop. Polling will not move it. If the user then agrees to research the captured names, call `start_campaign_run` again with `research_partial_roster: true`. Poll `get_run_status` only after a response has `ok: true` and a `run_id`. Report stage changes in a short line, not every poll. If the run parks at the quality gate, say so and offer `resume_quality_gate`.
9. When drafting is done, give a short summary from `campaign_stats`: people found, qualified, drafted. Suggest the `sayintel-review` command as the next step.
